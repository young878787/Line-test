# 啟動空白與逾時修正

## 已確認的原因

`uv run python n8n/service.py` 確實會建立 n8n 子程序，編輯入口是 `http://127.0.0.1:5680`；它不會自動彈出瀏覽器。

使用者這次輸出顯示，程式卡在 `NodeRuntime.ensure()` 等待 `/rest/settings`。外層 `asyncio.timeout(120)` 到期後取消正在等待 HTTP 回應的 coroutine，所以 traceback 先出現 `CancelledError`，最後轉成 `TimeoutError`。這不是使用者按 Ctrl+C，也不是 n8n 登入失敗。

原啟動器有三個缺口：

1. 固定只等 120 秒。當次初始化沒有在期限內完成，supervisor 隨即回收 n8n。
2. n8n 設為 warning 等級；supervisor 第一行成功訊息又放在 n8n、adapter、MCP 都完成以後，造成等待期間前景和日誌都可能空白。
3. `TimeoutError` 未轉成可讀錯誤；清理結束再次寫入 failed 狀態時，先前保存的 error 欄位被覆寫。

同一份 n8n 實例在診斷重測約 56.6 秒完成初始化。修正後整合重跑也確實取得 `/rest/settings` 200。因此可確認不是固定無法啟動，但無法單憑這些資料斷定當次變慢是磁碟、防毒、快取或其他底層原因。

## 不應誤判的訊息

- 5682／5683 在啟動初期先占用 socket，當時 adapter 還沒開始處理 HTTP；只看到 listener 不代表整套服務已 ready。
- n8n 的 ready on port 訊息代表開始監聽；初始化期間 `/rest/settings` 仍可能是 404。保留 REST 檢查，避免過早開始 MCP 設定。
- Confluence credential 與內建 Python runner 警告在成功重測時也存在，沒有阻止本 workflow 啟動。本 workflow 不使用 Python Code node，沒有為此新增 runner 或修改全域 n8n 安裝。
- 診斷期間也觀察到外部 MCP registry 刷新失敗。安裝的程式碼以背景呼叫刷新，這個警告本身不足以證明它就是此次逾時的主因。

## 實際修改

| 位置 | 修改與用途 |
|---|---|
| `processes.py` | n8n 等待上限改為 300 秒，仍保有總期限；立即顯示 PID、editor URL 及日誌位置 |
| `processes.py` | 約每 5 秒回報耗時、最後 HTTP 狀態或連線錯誤類型；子程序提前退出就立即失敗 |
| `processes.py` | n8n 改 INFO 等級，正常初始化及 editor ready 訊息可寫入 `.runtime/n8n.log` |
| `processes.py` | 逾時轉成 `N8nStartupError`，包含期限、PID、最後探測與日誌位置，不輸出環境值或 API 本文 |
| `service.py` | 啟動立即顯示模式及後續階段；等待期間同步更新狀態檔的 PID、耗時及探測 |
| `service.py` | 清理後保留 error／error_detail；預期啟動錯誤用簡短訊息退出，不再留下該串取消 traceback |
| `tests/run_tests.py` | 整合測試等待期限配合啟動上限，避免測試工具比服務更早判定失敗 |

300 秒是有限等待上限，不是每次都固定等待五分鐘。收到 REST 200 就立即繼續啟動 adapter 與 MCP；Ctrl+C 仍可在等待期間停止並回收資源。

## 驗證與結果位置

`tests/test_service.py` 新增五個回歸案例：模擬第 121 秒才 ready、到期保留最後 HTTP 503、子程序 exit 7 提前失敗、暫時 ReadTimeout 後恢復，以及失敗後 socket 回收且錯誤仍保留。121 秒案例使用可控制的測試時鐘，不會真的阻塞測試兩分鐘。

完整整合仍執行原本的 28 案 mock 業務、17 案服務，以及真實程序啟動、n8n 子程序故障恢復、停止、重啟與公開 HTTPS 探測。業務 API 維持 mock，不更新真實 LINE endpoint。

完整重跑結果為業務 28／28、服務 17／17、常駐與恢復 6／6，公開 HTTPS 探測通過。修正後最後一次 n8n 初始化耗時 18.6 秒；額外以獨立 CLI 程序注入預期啟動錯誤，確認 exit code 1、可讀錯誤訊息，且沒有 Traceback 或 CancelledError。測試服務已停止，18567、5680–5683 均未占用。

固定最新結果：`logs/startup_fix.json`、`logs/service_tests.json`、`logs/runtime_tests.json`、`logs/latest.json`、`logs/public_https.json`。最後一次服務啟動／停止輸出在 `.runtime/test_service.log`，n8n 自身輸出在 `.runtime/n8n.log`。

重新啟動仍使用同一條指令：

```powershell
uv run python n8n/service.py
```

等待期間可從另一個 PowerShell 查看：

```powershell
Get-Content n8n/.runtime/service.json -Raw
Get-Content n8n/.runtime/n8n.log -Tail 30 -Wait
```
