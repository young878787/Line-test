## 單一啟動入口

在 `D:\Line-test` 執行：

```powershell
uv run python n8n/service.py
```

這是前景常駐服務，終端機要保持開啟。`n8n/run.ps1` 是同一入口的 PowerShell 包裝。本次沒有安裝 Windows Service 或開機排程。

啟動順序：檢查舊服務及鎖 → 獨占 adapter／gateway 埠 → 啟動專用 n8n → 啟動 adapter → MCP 驗證及更新同一 workflow → 發布 → 建立 HTTPS → 驗證及同步 LINE。

指令會啟動 n8n 服務；瀏覽器請開啟 <http://127.0.0.1:5680>。前景立即顯示啟動訊息，等待 n8n 初始化時約每 5 秒回報 PID、耗時及最後 HTTP 探測。n8n 最多等待 300 秒，超過後會顯示明確原因並清理資源；詳見 [啟動逾時修正](啟動逾時修正.md)。

### 切換原 Python 服務

1. 在原 Python 服務的終端機按 `Ctrl+C`，等 18567 停止。新入口不會自行結束舊服務。
2. 執行上面的單一啟動指令。
3. 查看 `.runtime/service.json`，等 `status` 成為 `ready`，並確認 `checks.endpoint_matches` 是 `true`。最新 webhook 使用其中的 `endpoint`。
4. 在 LINE 手機端進行真實對話驗收。這部分尚未由本次 mock 測試取代。

正式模式沿用根目錄 `.env` 與 `DATABASE_PATH`，預設為原本的 `D:\Line-test\bot.sqlite3`，因此保留使用者設定、記憶與待處理工作。只執行原有初始化／恢復機制，不執行 mock reset。原服務與新 adapter 不可同時領取正式工作。

必要設定為 `LINE_CHANNEL_ACCESS_TOKEN`、`LINE_CHANNEL_SECRET`、`CWA_API_KEY`、`AI_API_Keys`；另沿用 `AI_API_URL`、`AI_MODEL`、`LINE_MONTHLY_LIMIT`。環境變數優先於 `.env`，不把值寫進報告。新入口自行管理 HTTPS，不使用原主程式的 `LOCAL_TUNNEL_ENABLED` 開關。

### HTTPS 的重新取得與同步

沿用原專案 Cloudflare Quick Tunnel，每次可能取得不同的 `*.trycloudflare.com` 網址。隧道只指向 `127.0.0.1:5683`，公開路由只有 `GET /health` 與 `POST /webhook`。

每個新網址都先測公開健康、正確簽章 200、錯誤簽章 400，再查詢 LINE 既有 endpoint、測試新 endpoint、更新、重新讀取確認。候選驗證失敗就不覆蓋舊 endpoint，失敗每 60 秒重試；cloudflared 結束時回收程序並重新建立及同步。n8n 故障恢復也會重建隧道。

Quick Tunnel 不是固定域名。Cloudflare 將它定位為開發／測試用途，沒有 SLA，見 [官方說明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)。本次依照既有方式接入，沒有配置固定域名。

## 狀態、停止與故障

```powershell
Get-Content n8n/.runtime/service.json -Raw
```

| 狀態 | 意義 |
|---|---|
| `starting_n8n` | 等待專用 n8n 啟動 |
| `configuring_workflow` | MCP 驗證、更新、發布流程 |
| `verifying_https` | 本機可用，公開 HTTPS 或 LINE 同步尚未完成 |
| `ready` | 正式模式完成 HTTPS／LINE 同步；mock 僅表示本機可用 |
| `restarting_n8n`／`retrying` | 偵測故障並恢復同一 workflow |
| `stopping`／`stopped` | 清理中／停止完成 |
| `failed` | 啟動或 adapter 失敗，查看日誌後重新啟動 |

同一狀態檔保留實際 `service_pid`、`n8n_pid`、`workflow_id`、`n8n_restarts`、最新 `endpoint` 與 HTTPS 檢查。Windows venv launcher PID 可能不同於實際 Python PID。`ready` 不代表真實模型、CWA 或手機端業務已驗收。

`starting_n8n` 期間另有 `startup_elapsed_seconds` 與 `startup_probe`。失敗時的 `error` 及可安全顯示的 `error_detail` 會在清理後保留，避免只看到 failed 卻找不到原因。n8n 使用 INFO 日誌，保存在 `.runtime/n8n.log`。

原終端機按 `Ctrl+C`，或另一個 PowerShell 執行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File n8n/stop.ps1
```

停止會關閉 tunnel、停用 workflow、等待 gateway／adapter 請求完成，再回收本專案 n8n 程序樹。Windows 下 n8n 最後使用核對 PID 後的 `taskkill /T /F`；帳號、workflow 與 DB 保留，重啟沿用。不要直接強制關閉 supervisor，以免跳過清理。

服務鎖拒絕重複啟動。5680 必須符合本專案 PID 記錄及 n8n command line 才接管；5682／5683 被占用就失敗。Supervisor 每秒探測 n8n，連續兩次失敗後恢復並發布同一 workflow，再重建 HTTPS。Adapter 自身失敗會整體清理並標記 failed，由相同入口重新啟動。

回到原服務時，先停止本服務，再用原 Python 啟動方式。原隧道會重新取得及同步自己的 URL；停止新服務本身不會把 LINE endpoint 改回舊臨時網址。

## 隔離運行與完整測試

只啟動隔離服務供編輯：

```powershell
uv run python n8n/service.py --mock
```

固定時鐘、獨立 `.runtime/mock_bot.sqlite3`、假 token。CWA／AI／LINE 經 MockTransport，未知路由直接失敗。不建立公開 tunnel、不更新 LINE；聊天每秒補跑，背景排程暫停，由測試明確觸發。

完整驗證前先停止本專案服務，再執行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File n8n/test.ps1
```

驗證自行啟動／停止 mock 常駐服務，只重設固定 mock DB。包括 28 個業務案例、17 個服務及隧道案例，以及程序啟動、防重複啟動、n8n 子程序恢復、正式背景排程拓撲、停止及完整重啟。正式排程拓撲仍搭配 mock 業務服務。

另外建立真實 Cloudflare HTTPS，從公開網址測空事件驗簽及私有路由 404；仍使用 mock 業務設定，跳過真實 LINE endpoint 同步。`public_https.json` 的探測 URL 結束時已停止，不可作為正式 webhook。

| 固定證據位置 | 內容 |
|---|---|
| `logs/latest.json` | 28 案結果及每案證據引用 |
| `logs/cases/*.json` | SQLite 快照、輸出、mock HTTP；不保存 Reply token |
| `logs/service_tests.json` | 路由、驗簽、期限、取消清理、隧道生命週期 |
| `logs/runtime_tests.json` | 啟動、程序故障恢復、停止、重啟 |
| `logs/public_https.json` | 真實 HTTPS 空事件驗簽與公開隔離 |
| `logs/verification.json` | 單一 workflow、接線、版本及外部業務呼叫數 |
| `logs/*_validation.json` | 官方 MCP SDK／節點驗證 |
| `logs/source_manifest.json` | 原實作 commit 與 SHA-256 |

每案斷言資料及輸出，並非只看 execution 成功。故障注入會產生預期 error execution。真實 API、帳號額度、模型語意、手機收訊、長時間運行及大量使用者負載尚未驗證。

## 檔案與資料位置

新增的入口、程序管理、adapter、gateway、tunnel、workflow、測試、fixture、驗證產物與中文 docs 全在 `n8n/`。正式業務 DB 預設沿用根目錄原檔，避免複製成兩份不一致資料。

`.runtime/.n8n/` 保存專用 n8n 帳號、credential 及 workflow DB；整個 `.runtime/` 忽略版控。刪除它會失去該實例登入及憑證。`workflow.json` 匯出為未啟用；內部 Header credential 綁定實例，跨實例匯入須重接，本啟動器會自動建立／重用 5680 credential。

啟動時會重新套用 `scripts/build_workflows.py` 管理的節點參數與排程設定。若在 editor 調整這些參數，需同步修改生成程式，才會在下次啟動保留；`workflow.js` 是生成產物。

舊三個 workflow 已停用並封存，記錄在 `logs/migration.json`。目前日誌為 `.runtime/n8n.log`、`.runtime/tunnel/cloudflared.log`，supervisor 輸出於前景終端機。測試程序日誌在 `.runtime/test_service.log`，結果輸出在 `logs/test_output.log` 及 `logs/service_test_output.log`。
